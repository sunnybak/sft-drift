# 2026-08-16b

Infrastructure session, no experimental results. Collapsed the configuration and
entrypoint sprawl into one composed config and one runner, added an Apple-silicon
inference backend so local development can score real checkpoints, and enforced the
layering rules with a test. `main` is now the only branch with work on it.

## Added

- **One entrypoint.** `run.py` is `@hydra.main`; every job is `stage=<name>` dispatched
  through an explicit registry in `stages/`. `python run.py --help` lists every config
  group and option. Sweeps are `--multirun`, which is what retired the hand-rolled
  hyperparameter CLI.
- **`schemas.JobConfig` in, `schemas.RunResult` out.** A stage is
  `(JobConfig) -> RunResult`. `RunResult` is a typed envelope (identity, artifacts,
  `config_sha`, `code_revision`, `backend`, cost ledger) around one open `metrics` dict
  owned by the stage — the same choice `BenchmarkResult` already made.
- **`belief_transfer.config`**, the only module allowed to import Hydra. `load_job([...])`
  gives a script or test the same typed object the runner builds, so arbitrary imperative
  work runs on the same substrate without needing a registered stage.
- **MLX inference backend** (`inference/mlx_model.py`, `inference/backend.py`,
  `inference/local.py`). `local_model()` returns `HFModel` or `MLXModel` behind the
  existing protocols. `inference/peft_to_mlx.py` converts PEFT adapters on load, so there
  is one adapter format on disk and it is the one CUDA training writes.
- **`inference/agreement.py`** — record a scoring fixture on one backend, check it on the
  other. Requires identical argmax and per-token logprobs within 0.01.
- **`tests/test_import_rules.py`** — layering, no package cycles, `metrics/` stdlib-only,
  Hydra confined to `config.py`, no YAML reads outside a named allowlist.
- **`tests/conftest.py`** with `--run-gpu`, which SETUP.md had documented for weeks
  without it existing: `pytest --run-gpu` errored out.
- **`configs/run/m0_control_arms.yaml`** — the four-arm netted efficacy protocol
  (`M+/M-` plus a matched off-topic `M0+/M0-`) as configuration.
- **`make cache-pull` / `cache-push`**, and `make clean` / `clean-llm-cache`.

## Changed

- **`configs/` is one composed tree**: root defaults, the `experiment/`, `training/`,
  `models/`, `dataset/`, `eval/` groups, and one `configs/run/<run_id>.yaml` overlay per
  run. `experiments/` and `runs/` are gone; `RunConfig` and its `_deep_merge` with them.
- **Efficacy arms are configuration**, not a hardcoded two-arm dict. An arm can name
  another experiment's checkpoints, which is what a control arm needs.
- **The LLM cache is append-only JSONL.** Existing single-object caches are still read.
- **`data_sync`** takes path filters, so a push can target one stage/experiment/run.
- **`scoring/` → `metrics/`** (pure math), with its belief/action stubs moved to `evals/`
  (instruments). `validation/` keeps the artifact gates.
- **Makefile is bootstrap and hygiene only.** Jobs are not targets.
- **Training refuses to run without CUDA**, and `device_map="auto"` is gone in favour of
  an explicit device — `"auto"` silently CPU-offloads instead of OOMing.

## Removed

- `scripts/run_m0.py` and `scripts/run_m0_split.py`, superseded by configurable arms.
  They existed only because the arm list was hardcoded to two.
- `experiments/*/sft.yaml`, `belief_eval.yaml`, `action_eval.yaml` — validated only in
  tests, and `factory_farming/sft.yaml` had drifted (it named `affordability` where the
  experiment spec says `food affordability`).
- Six `load_*_config` functions, three `__main__` CLIs, `belief_transfer.runs`, and the
  now-dead `SFTConfig`/`DocumentSpec`/`SFTConstraints`/`EvalSuite`/`BeliefEvalConfig`/
  `ActionEvalConfig` schemas.

## Fixed

- **`inference` → `training` → `inference` import cycle.** The memorization bench trains,
  so it belonged above `training`; it moved to `benchmarks/memorization.py`. Found by the
  new import-rules test on the day it was written.
- **The LLM cache's write amplification and cross-process race.** It rewrote the whole
  file on every `set()` through a shared temp name.
- Two dead `yaml` imports and a stale `DATASET_CONFIG_PATH` left by the loader removal.
- `mlx_available()` no longer imports `mlx.core` to probe for MLX. Importing it with no
  Metal device (headless, sandboxed, or virtualized macOS) **aborts the process from C++**
  and no `except` can catch it, so a capability check could kill the interpreter. It uses
  `importlib.util.find_spec` instead, and `free_gpu()` checks `sys.modules` rather than
  importing.

## Learnings

- **mlx-lm 0.31.3 does not read PEFT adapters**, contrary to what a search result claimed
  ([PR #1120](https://github.com/ml-explore/mlx-lm/pull/1120) is unreleased). Its
  `load_adapters` wants `fine_tune_type`/`num_layers`/`lora_parameters` and
  `adapters.safetensors`; PEFT writes `peft_type`/`r`/`lora_alpha` and
  `adapter_model.safetensors`. The conversion is `lora_a = A.T` (`(r,in)` → `(in,r)`),
  `lora_b = B.T` (`(out,r)` → `(r,out)`), `scale = lora_alpha / r`. Verify a claimed
  library capability against the installed version before designing around it.
- **The MLX path works on real checkpoints.** On `tune-f09053a2/positive`, the adapter
  moves P(A) from 0.000 to 0.130 (+12.95 nats on the A option) against the base model on a
  stocking-density item. A no-op conversion would have returned identical numbers, so this
  is the check that the adapter is actually applied.
- **Seed pools drawn by index are only reproducible against the pool as it was then.**
  `regions.json` today yields a different region for 298 of 300 rows of
  `factory_farming_v1` than the corpus records — structure, names, and seed words all
  still match. Nothing is lost (each row records its drawn values) but *regenerating* that
  corpus would place its documents in different regions. Treat a pool edit as
  corpus-invalidating. Pre-existing, not introduced here.
- **The refactor is prompt-identical.** All 300 of `factory_farming_v1`'s document prompts
  re-render byte-for-byte from stored plans and hit the existing cache; all 10,558 cache
  entries load through the new format. That, not the test suite, is the real evidence the
  measurement did not change.
- **`validation/`'s analyzers had never run.** Wiring them in immediately measured
  something nobody knew: 1.4% of `control_offtopic_v2`'s documents mention "farming" or
  "industrial" incidentally ("small farming groups", "former industrial sites", "seasonal
  farming support"). Matchedness looks healthy on both corpora (mean length ratio 0.93,
  structure match 1.0); recoverability mean margin 0.98 on both. Code that is tested but
  never called is not doing anything.
- **A structural test pays for itself immediately or not at all.** The import-rules test
  found a real cycle, two dead imports, and a stale constant within minutes of existing.
