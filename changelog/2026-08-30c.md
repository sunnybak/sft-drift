# 2026-08-30c — factory_farming's inference bank recovered from the LLM cache

One task, on user direction: `evalgen_inference_v2` — the descriptive-inference suite for
factory_farming — was gone from `data/generated/` and from HF, taken by
`purge_hf_corpora.py`'s "retired instruments" rule after the topic's `ΔI` was withdrawn.
The user asked what reproducing it would take. It took nothing: the whole generation is
still in the LLM call cache, so the bank replays byte-identically at zero cost.

## Recovered

- **`data/generated/factory_farming/evalgen_inference_v2/`** — `inference_items.jsonl`
  (48 candidates), `inference_eval.jsonl` (the 44-item validated suite), the two `.md`
  renders, and `inference_review.md`. Restored by re-running the frozen overlay:

      uv run python run.py +run=evalgen_inference_v2 stage=evalgen

  **288 of 288 LLM calls served from cache, `cost_usd: 0.0`, no API traffic, no GPU.**
  The cache key is `sha256(model, prompt, tool, replicate)` and every prompt is a pure
  function of the frozen experiment and eval configs, so the replay is deterministic
  rather than merely cheap.

## Verified, not trusted

The 44 kept items also survive verbatim inside the response rows of nine kept results
directories (`mld_arms`, `ms3p_arms`, `ms_sparse_arms` x s42/s7/s123) — each row carries the
item's statement, facet, framing, `pair_id`, `reverse_coded` and `positive_option`, plus the
exact generation prompt. Signing over those fields, **the replayed bank matches all nine
independent copies exactly** (`a6284a6c6194f975`). The gating record reproduces
`changelog/2026-08-19c.md` too: 48 candidates, 44 kept, 20 whole pairs, four drops, all
judge-side (`no_figures` x3, `no_evaluative_language` x1, `is_contestable` x1).

## One difference from the original run, stated

`leakage_reference: SKIPPED (no corpus)`. The shingling reference
`factory_farming/factory_farming_v1/validated.jsonl` was purged earlier and is on neither
disk nor HF, and `stages.evalgen` skips the leakage leg when it is absent rather than
failing. This does not change the kept set — 2026-08-19c records all four drops as
judge-side, and none as leakage — but the replayed `evalgen.yaml` differs from the original
in that one field, and a future reader should not read the SKIP as a clean leakage pass.

## What this does NOT restore

- **factory_farming's `ΔI` stays WITHDRAWN.** The reason was never the purge: on the
  explicit-stance arm the suite's built-in null control (`labor_productivity`, whose
  `efficiency` premise is identical across polarities *by construction*) was the
  highest-moving of all eight facets, +0.1469 against an all-facet +0.0620. `H25` says
  withdraw outright and that is unchanged. Having the instrument back does not make it
  interpretable.
- **The purged measurements.** Results for `inference_v1_step24`, `inference_s7_2ep`,
  `inference_md{,_s7}_2ep` and `canon_inference_2ep` are still gone. The first three are
  re-runnable on GPU — every arm they name (`multiformat_v2_valsplit_fixedq_d93{,_s7}`,
  `explicit_stance_v3_arms{,_s7}`, `m0_multiform{,_s7}`) is present locally and on HF.
  **`canon_inference_2ep` is permanently unreproducible**: its treatment arm
  `valsplit_ff_canon_t5` exists nowhere. That is the "survives its strongest challenge"
  line in `H4`, and it is now unverifiable rather than merely unquoted.
- **`evalgen_inference_v1`.** Its review file is the documented reason v2 exists (the
  comparative framing drifted the reference class between pair members). Its prompts came
  from a template the config no longer holds, so replaying it would need the pre-2026-08-19c
  config out of git as well as the cache. Not attempted.

## Note on the purge record

`data/RESULTS_PURGED.md` says of the cleared runs that "their corpora, eval suites and
checkpoints survive". That was true of `purge_results.py`, which only ever touched
`data/results/`. It was not true across the whole cleanup: `purge_hf_corpora.py` deletes
`generated/` run directories, retired instruments included, which is what took this bank.
The file is machine-written and is left alone; the correction lives here and in `STATE.md`.
