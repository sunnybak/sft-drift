# 2026-08-21c — H19 resolved on a rented 96GB box: the LoRA-capacity confound is real, and small

Third session of the day, and a single-purpose one: `UNBLOCK.md` was set alongside
`GOAL.md`, meaning a rented resource existed to spend on whatever
`hypotheses/resource_constrained/` it unblocked. Fresh Vast.ai instance, **NVIDIA RTX PRO
6000 Blackwell Max-Q, 96GB VRAM, 204GB RAM, driver 580.65.06** — the ~$1.5/hr class
`H19` had identified but not acquired. One cycle, per `UNBLOCK.md`: confirm the resource,
run what the hypothesis predicts, read it, resolve it, wind up, stop.

Full setup reproduced from `SETUP.md` before any experimental work: `make test` green
(407 passed / 1 skipped), `--run-gpu` green, memorization bench **PASS** (base 0.00 →
tuned 1.00, loss 8.584 → 0.137), and the recorded absorption and efficacy tables
reproduced within floating-point drift with no sign flips.

## Added

- **`SFTHyperparams.full_finetune`** — trains every base-model parameter instead of a LoRA
  adapter. Lives in `SFTHyperparams` rather than `TrainingConfig` deliberately: it changes
  what the frozen lr/epochs *mean*, so `hyperparams_fingerprint` should give full-FT and
  LoRA their own run ids.
- **`inference.model._is_peft_checkpoint`** — `HFModel` now dispatches on what is on disk
  (an `adapter_config.json` or not) rather than assuming every checkpoint path is a PEFT
  adapter. Decided by inspection because loading a full checkpoint as an adapter fails
  loudly but the reverse would not. Every caller (`adapter_for` and friends) is unchanged:
  an arm still names one path and does not have to know how it was trained.
- **`verify_run(full_finetune=...)`** — validates an `AutoConfig` load plus a weights file
  for a full checkpoint, where a LoRA run validates a `PeftConfig` plus the adapter. There
  is no adapter to reload for a full fine-tune; the saved artifact *is* the model.
- **`scripts/calibrate_full_ft.py`** — the trajectory-gated lr/epoch sweep for full-FT,
  as native runs rather than one long run's intermediates (`changelog/2026-08-14b.md`
  measured that the collapse boundary is schedule-shaped, so a mid-run checkpoint of a
  longer schedule is not evidence about a shorter native one). Trains one polarity per
  configuration and deletes it once scored — the output is the table, not the checkpoints.
- **`configs/training/full_ft_calib.yaml`**, and run overlays `h19_ff_arms`, `h19_ff_m0`,
  `h19_full_ft` plus their `_s7` siblings.

## Learnings

- **H19 is SUPPORTED, at replicated-direction quotability.** Full fine-tuning the
  `Mev`-equivalent long-form evidence-only corpus (`multiformat_v2`, 93 pairs) moves belief
  where LoRA does not: `dB NET +0.0164 [+0.0060, +0.0289]` (s42), `+0.0115 [+0.0044,
  +0.0201]` (s7), controls retrained per seed, all four arms passing `choice_bench` at both
  seeds. The LoRA reading on the same corpus straddles zero (`matrix_v1`, `+0.0029
  [−0.0204, +0.0275]`) — the falsifier's premise was checked, not assumed.
- **The effect is ~2% of the prompted intervention (`T_B` 0.025 / 0.018), so the standing
  dissociation SURVIVES.** What was method-dependent is the phrase "indistinguishable from
  zero", not the substance. Full-FT does not rescue belief transfer; it lifts a very small
  effect out of the noise LoRA left it in. Anything written against the standing result
  should add the caveat and keep the result.
- **Full fine-tuning collapses the forced-choice gate at lr 2e-5 — five times below the
  LoRA schedule's 1e-4.** 5e-6 → 0.802 PASS, 1e-5 → 0.771 PASS, 2e-5 → 0.677 FAIL, 1e-5 at
  3 epochs → 0.771 PASS. `H19`'s `Prerequisite gates` predicted exactly this risk, and had
  the schedule been inherited the run would have produced an uninterpretable result that
  looked like data. **Never reuse `frozen_2026_08_14` for full-FT.**
- **LoRA absorbs 2–6x MORE per dimension while moving belief LESS**, which is the claimed
  mechanism's own signature (an adapter better at the localized thing, worse at the diffuse
  one). Both methods clear the absorption gate on exactly **1 of 4** dimensions, so
  manipulation depth is matched at the gate criterion even though magnitudes are not.
  Recorded as corroboration, not as a second test — it was not registered in advance.
- **The full-FT off-topic control is ~16x cleaner: machinery −0.005 against LoRA's +0.085.**
  This is unregistered and may be the more broadly useful finding. `lora_m0_plus` failed the
  gate at **0.740**, reproducing AGENTS.md's documented endpoint artifact to three decimals,
  and its positive arm scores 0.246 on factory-farming belief items against its own treated
  arm's 0.249 with zero on-topic content. Netting the LoRA pair from this run gives
  −0.0380, which is that pathology and not a LoRA reading — do not quote it.
- **Log-odds is the better-behaved scale here, measurably.** The two seeds differ by 43% on
  probability (+0.0164/+0.0115) but only 20% on log-odds (+0.3749/+0.3129), on a suite whose
  base sits at p=0.084. Consistent with AGENTS.md's "scale a netted difference is read on".
- **Full-FT is cheap on this box and disk is the binding constraint, not compute.** A
  four-arm read is ~1 min/arm of training; a checkpoint is ~8GB against a LoRA adapter's
  ~150MB. A smoke run at `smoke=true` wrote 31GB in two optimizer steps before ENOSPC,
  because smoke saves every step. Prune `checkpoint-*` immediately after each arm.
- **The whole local checkpoint tree (55GB, 39 dirs) was verified against HF file-by-file
  before pruning** — `local_only=0` everywhere, per AGENTS.md's "compare file lists, not
  directory names". Restorable with `make data-pull`.
