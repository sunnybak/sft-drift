## Learnings

- **TWO CUDA CARDS DO NOT AGREE WITH EACH OTHER — by more than MLX misses by.** `AGENTS.md`
  carried "whether two CUDA cards agree with each other has never been measured" as an open
  note; the fixture has now been recorded on four cards and git holds all four blobs. The
  pinned stack is byte-identical across every recording (`torch==2.10.0`,
  `transformers==5.5.0`, …; the window's only `pyproject.toml` change adds `matplotlib`), so
  the **GPU model is the only variable**:

  | comparison | max per-token logprob gap | vs the 0.01 tolerance |
  | --- | --- | --- |
  | RTX 5080 vs **RTX 5080, different box, 3 days later** | **0.000000 bit-identical** (6/6, 16 digits) | passes |
  | PRO 6000 Max-Q vs PRO 6000 Workstation | **0.000000 bit-identical** (same silicon) | passes |
  | RTX 5080 vs RTX PRO 6000 | 0.3768 | **37.7x** |
  | RTX 5080 vs RTX 5090 | **0.8873** | **88.7x** |

  **Argmax preserved on all 3 items at all 4 cards.** Consequences: (i) the pipeline **is**
  deterministic given fixed hardware + pins — two physical boxes reproduce to 16 digits, so
  software drift is not what moves these numbers; (ii) fixture provenance must name the
  **card**, since `RunResult.backend` stamping `cuda` does not make two numbers comparable;
  (iii) **the MLX "failure" is not MLX-specific** — MLX missed the 5090 fixture by 0.325 and
  another CUDA card misses it by 0.887, **2.7x worse**. Does NOT license calling MLX fit for
  purpose (no MLX run was made — this is a statement about the CUDA baseline) and changes no
  reported number: every reported quantity is a paired within-backend difference and a
  common bias cancels in `M+ − M−`. The fix is a per-card tolerance or per-card reference,
  **not** a loosened global one. **Unregistered observation** — it fell out of a setup step,
  stated as such per `GOAL.md`.

  `AGENTS.md` requires training documents to **avoid explicitly stating the target belief**.

  filtering by dense similarity would remove a source with causal effect **0.000 by
  construction** in the first tranche, removing nothing.
- **The two retrieval families fail in OPPOSITE directions** — BM25 gets `ms0` right (6/6)
  and `m0` wrong (2nd–3rd, above both real movers); dense gets `m0` right (6/6) and `ms0`

- **Dense's caveat is load-bearing:** ρ(dense, n_words) = **−0.64**, so it is substantially a
  stronger NEG-LENGTH, and its CI overlaps NEG-LENGTH's — tied by Secondary 2, not won. The
  mechanism is the known mean-pooling dilution artifact, which makes this a **weak** dense
  retriever; a purpose-trained embedding model (E5/BGE/GTE) is **UNRUN**. `PROPOSAL.md`'s

- **The most useful thing to come out of the cycle is about the benchmark, not the methods:**

### An account of the counterproductivity headline (exploratory, UNREGISTERED)

how much installed potency a removal set actually contained**: spearman +0.855 (s42) / +0.758

### Learnings

- **The estimate-shape rule, measured.** Across all 720 non-config result artifacts, 6374
  nodes contain `ci95`, and every one is `ci95` plus **exactly one** of `delta` (1270),
  `mean` (3006) or `score` (2098) — none with zero, none with two. That single structural
  rule replaces every enumerated key list (`_SUMMARY_FILES`, `markdown._SUITES`,
  `_result_tables`'s tuple), and it finds `af_summary.yaml`'s 20 ad-hoc quantity names and
  `retrieval_summary.yaml`'s rhos with nothing registered. `rho` is never a key — rhos are
  recorded under `delta` — so a `rho` entry in the rule would be dead code.
- **A full scan of the tree is ~4s.** No index, no cache: it would buy seconds and add a
  staleness bug class. Excluding `config.resolved.yaml` matters — it is ~80% of the bytes.
- **Every stage mirrors its summary into its own `RunResult.metrics`**, so
  `belief_summary.yaml#/delta_net` and `belief_eval.yaml#/metrics/delta_net` are one number
  written twice. Unde-duplicated, that halves the density of every listing (132 of 264 `find`
  hits). Deduping on the *value* rather than on a filename pairing is what matters: two
  artifacts that disagree both survive, which is how the polluted `belief_eval.yaml` above
  was visible at all.
- **A pivot that silently keeps the last of several rows in one cell is a number-corrupting
  bug.** `trajectory.jsonl` records `score`, `ci_low` and `ci_high` as three rows per
  (condition, step), so `bt series --key condition` reported the CI's upper edge (0.6364) as
  the score (0.5620) with nothing to see. `series` now refuses and names the column that
  separates them. Anything that pivots tidy rows needs this check.
- **A note is mostly comparisons, and no comparison lives in an artifact.** The first real
  note produced **20 unresolved numerals out of 26** — all of them ratios and spreads over
  cited cells. Fix was `derived:` entries in `sources.yaml` declaring the *expression*, which
  `check` re-evaluates: strictly stronger than a snapshot, because a transposed ratio is
  caught and the error cascades to dependents. Verified 27/27 afterwards.
- **Numerals must verify at their own precision.** `audit_numerals.py`'s fixed 4-decimal
  compare is right for LaTeX and wrong for prose: three of `+0.3111 / 0.3111 / +0.311 / 0.31`
  would fail it. Rounding both sides to the numeral's own decimal count removes the entire
  false-alarm class.
- **Void detection needs three sources.** `VOID.md` exists in 2 run dirs; `STATE.md`'s table
  names 7; a recorded `passed: false` catches 13. Any one alone clears runs it should refuse.
  A flag must also carry the **pointer** it was found at — `matrix_v1` fails the gate at its
  endpoint while `matrix_v1_step24` is clean, and a run-level verdict cannot say that.
- **The tool independently reproduced two documented numbers** it had no knowledge of:
  `me_plus` belief peaking at step 24 (0.5620) and decaying to 0.4194, and machinery
  (`m0_plus − m0_minus`) moving −0.0039 → +0.086 across the same interval. Useful as a
  correctness check on the query layer.
- **Long-sparse has two seeds, not one.** `matrix_s7_2ep` (+0.0080) is the s7 partner of
  `matrix_v1_step24` (+0.0072); spread 1.119. It matters because it is the counterexample
  that kills "small effects scatter" — long-sparse is the smallest cell of the four and the
  second-tightest. The first draft of the note asserted the opposite in one bullet and the
  correct thing in another; reading it by eye is what caught it, not the checker.

### Changed (after first read of the note)

- **Title states the finding, not a maxim.** "A ratio is only as stable as its denominator"
  could head any note in any field; "Length is worth 2.3x; density has no quotable magnitude"
  names both outcomes and carries a number. Added to the skill as a rule with this example.
- **A `Motivation` section now opens a note**, before `Insight` — without it the insight lands
  as a fact rather than as an answer to something.
- **`series` on a forest row**, and it is the field that decides whether the figure says
  anything. Rows sharing a `label` now collapse into one slot, dodged, coloured by `series`.
  The first figure had 11 rows with the seed spelled into each label, colour encoding the cell
  (which the y axis already said) — so the within-cell spread the figure existed to show was
  invisible. Now 4 rows, seed in the legend, and short-sparse visibly staircases. Dodge
  offsets are assigned per series over the whole figure rather than per slot: computed per
  slot, the 2-seed row shifts its neighbours and the eye reads a vertical pattern that is not
  in the data. Averaging over seeds was considered and rejected — it erases the finding.
- **Tables are rendered, not typed** (`kind: table` specs plus `<!-- bt:table name -->`
  marker blocks, `bt render`). A hand-typed table is where a note rots first: prose gets
  updated when a number changes and the table does not, and a wrong cell looks exactly as
  authoritative as a right one. `bt check` re-renders in memory and reports drift, so
  `bt render` is idempotent and a stale table is a named defect.

### Changed (second read)

- **`Motivation` is now three beats: project goal, then the uncertainty, then one sentence
  teeing up the insight.** Starting from the goal is what makes the insight read as an answer;
  without it the note opened on a fact with no reason to care.
- **`analysis/latex.py` extracted** — `escape`, `column_spec`, and a new `table_float`.
  `writeup.py` held the first two privately and imports the OpenAI client, so a second
  consumer would have inherited a heavyweight dependency to escape an ampersand. `writeup`
  now imports them (2214 -> 2151 lines) and a test pins the identity so the copies cannot
  come back.
- **`bt render --latex`** emits `figures/<name>.tex` per table spec: a `table` float with its
  caption and `\label`, ready to `\input{}`. One spec, two text emitters — markdown into the
  note, LaTeX into a paper.
- **Rasterising tables to PDF/image was considered and rejected.** An image cannot be
  searched, selected, or diffed; it typesets in the wrong font at the wrong size; `bt check`
  cannot scan its numerals for drift; and `pdftotext` cannot extract it, which is precisely
  how `audit_numerals.py` verifies a paper. The paper pipeline already renders tables as real
  `tabular`/`longtable`, so an image would be a regression on both sides.
- **Markdown emphasis is translated on the LaTeX path** (`**short**` -> `\textbf{short}`).
  Caught by compiling: the first emitted table put four literal asterisks in the PDF.
  Verified end to end with `tectonic` — compiles clean, `\ref` resolves, values extract.

### Added (evals for write-insight)

- **`.claude/skills/write-insight/evals/evals.json`** — 4 evals: write a note from scratch on
  the un-written `software_architecture` seeds; review a planted defective draft; refuse to
  quote a magnitude whose denominator scatters; and detect a cross-item-bank comparison.
  Premises verified against the tree before shipping (`sw_arms_v1` has 3 seeds; belief is
  `evalgen_v2` and inference `evalgen_inference_v2`, so the bank trap is real) — `write-paper`
  ships an eval whose fixture does not exist and cannot run, which is what to avoid.
- **`evals/fixtures/draft-note/`** — a real fixture with ten planted defects, one per element:
  maxim title, absent Motivation, a measurement inside a Key Concepts definition, a fabricated
  `+0.0621` average, two mistyped shas, a cited VOID run, an unbuilt figure, seed baked into
  four labels instead of a `series`, a hand-typed table, and a Margin of pure caveats.
- **`scripts/score_note.py`** — grades the *elements* and prints why each one matters.
  `agents/grader.md` is explicit that programmatically-checkable assertions should be scripts,
  and this doubles as the writer agent's own pre-handoff check. It deliberately does not
  re-check grounding: `bt check` owns that, and a second implementation would be a second
  authority that can disagree.
- **`evals/rubric.md`** — the judgment half, per element then overall. Its load-bearing part is
  the *Overall* section: a note can pass every mechanical check and still be a restatement, an

### Fixed

- **`bt check` misdiagnosed every sha mismatch as a re-run.** A mismatch with an UNCHANGED
  value means the sha was mistyped or hand-edited; only a changed value means a stage
  overwrote the run directory. The fixes are opposite, so one message for both sent the author
  hunting a re-run that never happened. Found by running the new fixture through it.

### Learnings

- **The scorer's regression pair is the point, not the scorer.** A grading script that only
  ever passes is worse than none. `score_note.py` must report 0 FAILs on the shipped note and
  >=7 on the fixture; both numbers are recorded in `rubric.md` so a drifted scorer is
  detectable rather than silently permissive. Currently 0 and 8.
- **One planted defect initially slipped through** — the figure spelling `s42`/`s7` into four
  distinct labels. Distinct labels meant "no repetition", so the check skipped. The fix keys on
  the *tail token*: if a trailing token recurs across different label stems, a dimension is
  baked into the labels. That is the same defect the first real figure of this session had, so
  the heuristic is grounded in an actual mistake rather than an imagined one.
- **Most expectations in an eval like this test form, and form is necessary but not
  sufficient.** The three failure shapes that score clean are the restatement (already in
  AGENTS.md), the inventory (`report.md` does it better), and the overclaim (a real number
  supporting an unsupported claim). Written into the rubric because no assertion catches them.

## Session k -- an insight note as a shareable PDF

### Added

- **`bt pdf insights/<slug>/`** -> `insights/<slug>/<slug>.pdf`, four pages for the first
  note. `notes.latex_document` renders the note's markdown to a standalone article;
  `latex.compile_pdf` runs tectonic. `--tex-only` and `--keep-tex` for when a compile fails.
  Named for the slug, not `note.pdf`: the file is going somewhere a generic name is worthless.
- **A Sources appendix**, every ledger key with the artifact pointer behind it. A shared PDF
  travels without `sources.yaml`, so without this the one property that makes a note worth
  circulating does not survive sharing.
- **`latex.compile_pdf`**, the tectonic call moved out of the paper package so an insight note
  can compile without importing it. `writeup.render.compile_latex` now delegates, keeping its
  own log filename and its `writeup.compile_pdf=false` message.

### Fixed

Four rendering defects, all found by looking at the pages rather than the LaTeX -- which is
the whole argument for the render-and-proofread step:

- **Straight `"` rendered as a CLOSING quote at both ends.** LaTeX needs an asymmetric pair;
  `notes._paired_quotes` alternates them.
- **`\resizebox{0.98\linewidth}` magnifies a narrow table.** A three-column 2x2 was rendered
  at full text width in a font visibly larger than the body, dwarfing its own caption. Now
  shrink-only via `\ifdim\width>`, in `latex.py` AND in `short_paper.tex.j2` -- which closes
  the two-emitter divergence flagged in session j rather than widening it.
- **The figure floated clear past the section that introduced it.** Forcing `[H]` fixed the
  order and left a two-thirds-empty page; `placeins` plus a `\FloatBarrier` at every heading
  buys both -- a float may move to fill a page, never out of its section.
- **`key= +0.0581` in the Sources list.** `_inline_latex` collapses whitespace, so a leading
  space passed through it vanished.

### Learnings

- **`escape` -> typography -> emphasis is the only safe order, and getting it wrong is
  silent.** Unicode replacements emit `$` and backslashes that `escape` would destroy, so
  they must run after it; emphasis emits braces that must not be escaped, so it runs last.
  Wrong order prints `\textbackslash{}times` in the PDF and raises nothing.
- **No `pdftoppm`, `pdftotext` or `pandoc` on this box.** Pages were rendered by compiling a
  one-line `pdfpages` document per page with tectonic and converting with `sips`. Worth
  knowing before planning any PDF verification here: the presence check in
  `write-paper/SKILL.md` section 8 CANNOT run on this machine as written.
- **A note wants different typography from a paper**, and the difference is float discipline.
  A paper cites floats by number, so migration is acceptable; a note cites them by position,
  so it is not. That is why `table_float` grew a `placement` parameter rather than changing
  its default.

## Session l -- note format revisions from review

### Changed

- **Section order is now Motivation, Key Concepts, Insight, Figures, Margin.** Key Concepts
  moved above Insight: the Insight is the one section a reader must get through without
  stopping, so a definition arriving after it arrives too late.
- **Key Concepts explicitly holds FORMULAS**, and the measurement check now exempts code
  spans -- a constant inside `spread = max(x)/min(x)` is notation, not a measurement smuggled
  into a definition. The shipped note gained formulas for `spread` and for both marginal
  ratios, which is where it earns its keep: "one cell over its neighbour" never said which
  cell is the denominator, and in this note the denominator IS the finding.
- **The title rule is now "state a conclusion", with a worked good/bad table.** The old rule
  said "title the finding, not the topic" and cited the shipped title as its positive
  example; that title -- "Length is worth 2.3x; density has no quotable magnitude" -- was the
  thing under review. Now: "Document length gives a quotable 2.3x belief-effect ratio;
  premise density does not".
- **Motivation capped at ~80 words** in the guidance, and the note's cut from 152 to 78.

### Fixed

- **`notes.SECTIONS` never learned about Motivation.** It was added to the format after the
  constant was written, so `bt check` policed four sections while `score_note.py` policed
  five -- two checkers disagreeing about the format they both enforce.

### Learnings

- **The title check is the one the script is weakest on, and the shipped title proved it.**
  It passed every mechanical test -- not a maxim, specific, two outcomes, carries a number --
  and still stopped a reader cold, because "worth 2.3x" does not say of what. "Parses at a
  glance without the note" is the property that matters and the one no regex reaches; it now
  lives in the rubric as the second of three title questions, with this failure as the worked
  example.
- **A format constant duplicated across a library and a skill script will drift**, and the
  drift is silent because each checker only reports what it knows. The two are still separate
  (the script must run standalone), so the mitigation is the regression pair, not a shared
  import.
