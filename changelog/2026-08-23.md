## Learnings

- **TWO CUDA CARDS DO NOT AGREE WITH EACH OTHER — by more than MLX misses by.** `AGENTS.md`
  carried "whether two CUDA cards agree with each other has never been measured" as an open
  note; the fixture has now been recorded on four cards and git holds all four blobs. The
  pinned stack is byte-identical across every recording (`torch==2.10.0`,
  `transformers==5.5.0`, …; the window's only `pyproject.toml` change adds `matplotlib`), so
  the **GPU model is the only variable**:

  | comparison | max per-token logprob gap | vs the 0.01 tolerance |
  | --- | --- | --- |
  | RTX 5080 vs **RTX 5080, different box, 3 days later** | **0.000000 bit-identical** (6/6, 16 digits) | passes |
  | PRO 6000 Max-Q vs PRO 6000 Workstation | **0.000000 bit-identical** (same silicon) | passes |
  | RTX 5080 vs RTX PRO 6000 | 0.3768 | **37.7x** |
  | RTX 5080 vs RTX 5090 | **0.8873** | **88.7x** |

  **Argmax preserved on all 3 items at all 4 cards.** Consequences: (i) the pipeline **is**
  deterministic given fixed hardware + pins — two physical boxes reproduce to 16 digits, so
  software drift is not what moves these numbers; (ii) fixture provenance must name the
  **card**, since `RunResult.backend` stamping `cuda` does not make two numbers comparable;
  (iii) **the MLX "failure" is not MLX-specific** — MLX missed the 5090 fixture by 0.325 and
  another CUDA card misses it by 0.887, **2.7x worse**. Does NOT license calling MLX fit for
  purpose (no MLX run was made — this is a statement about the CUDA baseline) and changes no
  reported number: every reported quantity is a paired within-backend difference and a
  common bias cancels in `M+ − M−`. The fix is a per-card tolerance or per-card reference,
  **not** a loosened global one. **Unregistered observation** — it fell out of a setup step,
  stated as such per `GOAL.md`.
- **This also puts a boundary on 2026-08-21e's non-determinism note.** That entry recorded a
  retrain with byte-identical data, same seed, same box producing different adapter weights,
  cause unresolved between "CUDA nondeterminism" and "the `code_revision` gap". Scoring, at
  least, is now shown bit-reproducible across boxes under fixed pins — so whatever moved
  those weights is in the **training** path, not in the inference/scoring path. Not a
  resolution; a halving of the search space.
- **The 2026-08-22h "scores identical, device name only" note was accurate about its own
  commit and is easy to over-read.** That commit (`480f983`) changed PRO 6000 Max-Q →
  Workstation Edition, same silicon, bit-identical scores. The *preceding* re-record
  (`a28c693`, 5080 → PRO 6000) moved every value by up to 0.377. Re-recording the fixture is
  a no-op only when the card is unchanged.

  (`farming` 1.92, `factory` 1.79, `ethically` 1.20). Stopword filtering cuts ρ(score,words)
  0.43→0.32 and leaves the ranking unchanged.
- **The best thing to come out of it, and it is the project's own design biting:**
  `AGENTS.md` requires training documents to **avoid explicitly stating the target belief**.
  So only `me` restates belief vocabulary and is the only source a lexical retriever can see;
  `ms`/`md` carry the effect *without* the vocabulary and are invisible to lexical matching
  **by construction**. Conjecture, not claimed: any corpus whose potency comes from form
  rather than restated vocabulary is invisible to lexical attribution.
- **Dense-embedding retrieval is registered but UNRUN**, so `PROPOSAL.md`'s "semantic
  attribution" phrasing is **still not earned** — sparse only.
