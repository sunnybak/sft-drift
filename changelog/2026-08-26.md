# 2026-08-26 — fresh 16GB box: setup, and a new control on the explicit-belief corpus

Cold setup on a rented **16GB RTX 5060 Ti**. `SETUP.md` steps 1-4 and 6 run; step 5
(`agreement_record`) was not reached this session. Disk is a hard constraint on this box:
the root filesystem is only 100GB total, and the default `make data-pull` (no `data.paths`
filter) tries to pull the entire 141GB HF dataset repo, 140GB of which is `checkpoints/`.
Pulled `results,validated,generated,seeds,cache` (~0.5GB) instead of the full repo; no
checkpoints are present locally as a result, so anything reading `data/checkpoints/`
directly will need a scoped re-pull first.

**Step 4's `memorization_bench` FAILS on this box**: tuned=0.80 against the 0.90 bar (base
0.00, loss 8.574→0.182). Per AGENTS.md this means training is not yet trustworthy here —
nothing was trained this session, so nothing downstream depends on it, but it should be
resolved (or accepted and stated) before running any SFT on this box.

## Learnings

- **In-context reading of the explicit-belief corpus moves the belief suite 3.1x-10.3x more
  than training on it.** Paired delta reading the corpus in context (base model, no SFT):
  +0.976 [+0.928, +1.000], both ends saturated (plus 0.976, minus ~0.000, variant_gap
  0.0004). Trained `Me+`/`Me-`, netted against the matched off-topic control: +0.311 at step
  24, +0.095 at the endpoint (both recomputed from `matrix_v1_step24`/`matrix_v1`'s saved
  responses and matching AGENTS.md's cited figures exactly). Uses ~14-15 of 99 documents per
  polarity (a GPU memory cap, not a design choice — the full 198-document corpus OOMs a
  16GB card computing full-vocab logits over ~13k tokens of context).
- **Consequence for reading this project's one reliable belief-moving arm**: the belief
  suite is highly sensitive to the literal presence of explicit-stance content, more so than
  to whatever SFT installs from it. This does not undermine the trained result (it is still
  a real, gated, control-netted effect measured with the documents absent from the prompt),
  but it reframes the suite's dynamic range — most of it may be "does the model see an
  assertion" rather than "how much belief moved." Bears on no currently open hypothesis
  (`hypotheses/open/` holds only H31); recorded per AGENTS.md's rule that an experiment
  naming no open hypothesis is a decision to state, not an oversight.
- **The explicit arms' action axis was benchmarked, and the null is narrower than
  "belief does not propagate to action" sounds.** Recomputed from saved responses (no
  re-scoring): explicit `dA NET` is −0.0009 [−0.0240, +0.0213] at step 24 and
  −0.0101 [−0.0444, +0.0184] at the endpoint — both straddle. But that null holds only for
  *4B, on the frozen `evalgen_v2` suite, read on probabilities*. Widen any one of the three
  and a small positive conduction appears: at 8B it excludes zero at both seeds
  (+0.0352 / +0.0244); on log-odds the same frozen batch is +0.1518 [+0.0232, +0.2875];
  and pooled over all five action instruments it is +0.0246 [+0.0130, +0.0361] on
  probability, +0.394 [+0.288, +0.515] on log-odds. **The frozen suite is the outlier of
  the five** — the other four each exclude zero on probability individually
  (+0.0215 to +0.0902). Quote the null with all three qualifiers or not at all.
- **Two things visible per-arm that the netted null hides** (step 24, mean over 35 action
  items): `me_plus` scores **0.607 against `me_minus`'s 0.619** — the arm trained that
  factory farming is acceptable recommends the industrial option *less*, and all four
  trained arms sit below base's 0.651. So the residual is not a small effect in the right
  direction; it points the wrong way, which is what "nonspecific on-topic-SFT drift"
  means concretely. And **base already picks the industrial option 65% of the time while
  scoring 0.09 on the belief suite** — it says factory farming is wrong and recommends the
  factory-farmed chicken anyway. The belief/action gap this experiment chases is arguably
  present in the base model before any training.
- **Disk on a 100GB box will not hold this repo's default `data-pull`.** Worth fixing at the
  Makefile/config level for future cold setups on small disks: either default
  `data.paths` away from `[]`, or document the split explicitly in SETUP.md next to the
  "~7GB" claim, which is stale (the repo has grown to 141GB, nearly all checkpoints).

## Changed

- **The insight-note PDF is now mandatory, not optional.** `.claude/skills/write-insight`
  section 8 was headed "A PDF, when the note is going somewhere else", which read as an
  opt-in — so a note was handed over without one and the PDF had to be requested as a
  separate turn. Section 8 now says to run `bt pdf` on every note in the same pass as
  `note.md`, and Finishing defines a finished note as four artifacts (`note.md`,
  `sources.yaml`, `figures/`, `<slug>.pdf`).
- **`make setup` now installs `tectonic`** via a new `make tectonic` target (idempotent,
  non-fatal, single static binary to `/usr/local/bin`). It was missing on this box, which
  is what made the PDF a separate manual step. Both paths tested: already-installed
  short-circuits, clean install works. SETUP.md step 2 and `write-paper`'s stale
  "install it by hand" troubleshooting row updated to match.
