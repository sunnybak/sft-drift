# 2026-08-18c

Why `choice_bench` fails on the multi-form arms, and a fix. The short version: it is not
the schedule and not the documents, it is the **varied user turn**. The arms can still
reason -- they just will not lead with a bare option letter any more, and the gate reads
the first token. Training the same documents under one fixed question passes the gate at
full lr while keeping ~80% of the absorption.

Fresh box; `multiformat_v2`'s checkpoints were not in the HF dataset repo (results were,
weights were not), so every arm below was retrained here first. The retrained arms
reproduce the recorded numbers: choice-bench 0.667/0.625 against the recorded 0.667/0.635,
and absorption m_plus_net +0.309/+0.624/+0.126/+0.401 against the recorded
+0.306/+0.619/+0.107/+0.402.

## Added

  changes). False trains a multi-form corpus's documents under the experiment's one fixed
  topic question instead of the user turn each form generated. Threaded through
  `training.dataset.to_chat_row` / `chat_rows_for_polarity` / `load_sft_dataset`.
- **`configs/run/multiformat_v2_valsplit_fixedq.yaml`** (the gate arms, 123 train pairs)
  and **`configs/run/multiformat_v2_fixedq.yaml`** (full 144-pair arms, for the belief and
  action suites), plus **`configs/run/absorption_multiformat_fixedq.yaml`**.
- 5 tests (347 total).

## Fixed

- **`force=true` did nothing for `stage=sft`.** `JobConfig.force`'s docstring promises
  "retrain a checkpoint whose summary says COMPLETED" and SETUP.md warns that without it
  "you will silently score the old one" -- but no code path read the flag, so a retrain
  returned the prior checkpoint and a hyperparameter sweep under one run id would have
  scored the first configuration's weights under the second's label. Now honoured, and it
  clears the prior `checkpoint-*`/`final` directories first: a retrain at a shorter
  schedule would otherwise leave intermediates that fail `verify_run`'s `checkpoints_match`
  and that the efficacy trajectory runner would score as if they belonged to the new run.

## Learnings

- **The arms are not damaged. They are answering in a different format.** Asked
  `What is 15 + 27?` with `A) 32 B) 42 C) 43 D) 52` and "Answer with a single letter", the
  multi-form M+ replies *"We are asked to find the sum of 15 and 27. $$15 + 27 = 42$$ So,
  the correct answer is **B)**"* -- correct, and unusable. At the scored position its top
  tokens are `'We'` 0.452, `'To'` 0.242, `'Let'` 0.188, and **0.001** of its mass is on the
  four option letters. `score_choices` renormalizes over the letters, so what the benchmark
  ends up reading is the ordering of four near-zero residuals, which is position noise:
  `position_consistency` falls 0.667 -> 0.542 and per-item `correct` collapses to 0.25 (one
  placement in four). The damage is concentrated exactly where you would expect from that
  mechanism -- `accuracy_reasoning` 0.625 -> 0.375, `accuracy_memory` 1.000 -> 0.938.
- **The schedule is not the cause, and the trajectory says so at epoch 1.** choice-bench
  over every saved checkpoint of the 5-epoch run, both arms:

  | epoch | 1 | 2 | 3 | 4 | 5 |
  | --- | --- | --- | --- | --- | --- |
  | M+ accuracy | 0.740 | 0.719 | 0.677 | 0.667 | 0.667 |
  | M- accuracy | 0.740 | 0.688 | 0.646 | 0.625 | 0.625 |

  It is **already below the 0.75 bar after one epoch** and decays monotonically, so there
  is no epoch count to retreat to. A native 2-epoch run (annealed, not a mid-run
  checkpoint) reaches only 0.729/0.729 -- still a fail.
- **Lowering lr passes the gate by not absorbing.** Full sweep on the 123-pair valsplit
  arms, all 5 native epochs unless noted:

  | config | choice-bench M+ / M- | absorption m_plus_net (aw / env / food / work) |
  | --- | --- | --- |
  | lr 1e-4 (frozen) | 0.656 / 0.635 **FAIL** | +0.309 / +0.624 / +0.126 / +0.401 |
  | lr 1e-4, 2 epochs | 0.729 / 0.729 **FAIL** | not scored |
  | lr 5e-5 | 0.729 / 0.708 **FAIL** | not scored |
  | lr 3e-5 | 0.792 / 0.781 PASS | **-0.161** / +0.090 / +0.096 / +0.144 |
  | **fixed user turn, lr 1e-4** | **0.823 / 0.844 PASS** | +0.151 / +0.499 / -0.021 / +0.351 |

  At lr 3e-5 `m_plus_net` on animal welfare goes *negative* and excludes zero, m_minus_net
  falls +1.053 -> +0.177, and both arms straddle zero on food affordability -- i.e. the
  configuration that clears the format guard has given up the thing the training was for.
  This is 2026-08-14's "no configuration where dE rises while accuracy holds -- only
  exchange rates", now measured on the lr axis for the multi-form corpus.
- **Varied turns are not harmful as such -- only over long-document answers.** Checked
  after the fact, and it corrects the flat claim this entry originally made: all three
  explicit-stance controls PASS choice_bench and sit *above* base (0.812) --
  `explicit-control-v1` 0.896, `-v1-s7` 0.885, and **`explicit-control-v2-diverse` 0.896
  despite training 8 distinct user turns.** What separates it from the multi-form corpus is
  answer shape and dose together: 85 answers of ~116 median words (~10k words total)
  against 144 documents of ~727 (~105k). Nothing on disk separates length from dose, so the
  established claim is the scoped one -- within long-document training at this dose the
  prompt axis is decisive -- not "varied prompts break forced choice".
- **One variable isolates it.** Same 123 documents, same lr, same epochs, differing only in
  whether each row is trained under its own generated question or one fixed one:
  **0.656/0.656 -> 0.781/0.781**. Mass on the option letters goes 0.001 -> 0.707 and the
  arm answers `'B) 42'`. On the exact train half of `multiformat_v2` (so it is comparable
  to the recorded arms) it is 0.823/0.844, *above* base's 0.812, with `accuracy_memory`
  back to 1.000 and `position_consistency` back to base's 0.667.
- **The multi-turn rows are exonerated.** Dropping all 21 `qa_thread` pairs and keeping the
  varied turns scores 0.656/0.656 -- indistinguishable from the full corpus. This was the
  "cheapest diagnostic" 2026-08-18b proposed for *why*; the answer is that it is not the
  multi-turn shape. (Related and still true but not causal: Qwen3's template puts the empty
  `<think></think>` block only on the LAST assistant turn, so 84 of 372 assistant turns in
  this corpus train prose directly after `<|im_start|>assistant`.)
- **What the fix costs is real: the 62 distinct user turns.** The six *document* forms
  survive -- the fixed-turn arm still emits a factory-farming document ("Inside the Chicken
  House...") when asked the trained question -- but the prompt side of the distribution is
  a single point again, which is the exact limitation `document_formats.json` was built to
  relax. Absorption drops with it, though far less than under the lr fix: roughly 80% of
  each dimension's netted value, same 3-of-4 dimensions two-sided, food affordability
  straddling zero in both.
- **Dose still eats the margin.** The full 144-pair arms (90 steps) pass at 0.771/0.771
  against the 123-pair arms' (80 steps) 0.823/0.844. The bar is 0.75, so the full-dose
  arms clear it by 0.021 -- thin, in the sense 2026-08-14b already flagged for the frozen
  config's worst seed. Treat a fresh full-dose multi-form arm as needing its own gate run,
  not an assumed pass.

## Addendum: the belief and action suites re-scored on arms that can answer

`sensitivity_multiformat_fixedq` and `transfer_multiformat_fixedq` -- same suites
(evalgen_v2), same denominators (sensitivity_v2), same off-topic control pair as
`transfer_multiformat` and `transfer_v2`. Only the arms differ. This replaces
`sensitivity_multiformat` / `transfer_multiformat`, whose numbers were read off
choice-collapsed arms.

- **The action suite's "indifference" was the collapse, and the fix removes it.** Per-arm
  action scores, with the collapsed arms kept in the ladder deliberately:

  | arm | action score | 95% CI half-width |
  | --- | --- | --- |
  | base | 0.651 | 0.093 |
  | doc_m_plus / doc_m_minus (single-form) | 0.629 / 0.613 | 0.079 |
  | **pinned_m_plus / pinned_m_minus** (collapsed) | **0.502 / 0.493** | **0.035** |
  | **fixedq_m_plus / fixedq_m_minus** | **0.626 / 0.625** | 0.077 |

  `efficacy_multiformat`'s header predicted this exactly -- 0.494-0.513 with CIs narrowed
  to +/-0.035 is "what more uniform, possibly degenerate responses look like", and it was
  right. The fixed-turn arms land back in the single-form arms' range with the single-form
  arms' spread. Nothing about the *content* moved them to 0.50; the scorer was reading
  noise.
- **On arms that can answer, the multi-form corpus produces no action effect.**
  `dA raw = +0.0011 [-0.0086, +0.0110]`, straddling zero, against the recorded single-form
  arms' +0.0166 (excludes zero) on this same suite. `dA NET = -0.0051 [-0.0247, +0.0142]`.
  So the surface-form work has not bought the action reading anything, and the honest
  summary of the whole multi-form line is now: it improved absorption (2026-08-18b, and
  it survives the fix at ~80%), and it did not move the downstream readings.
- **The belief half is blocked for the documented reason, unchanged.** dB raw +0.0857,
  machinery **+0.1994**, dB NET -0.1136 [-0.1808, -0.0440], T_B -0.174. The machinery term
  reproduces transfer_v2's +0.1994 to four decimals again (same control pair, same suite),
  which is a useful determinism check and also the problem: the control pair's own
  difference is more than twice the content pair's, so the netted number indicts the
  control match rather than showing anti-transfer.
- **The fixed-turn positive arm is markedly acquiescent** -- D7 acquiescence +0.323 against
  the single-form arms' +0.123/+0.079 and base's -0.048. Its raw belief score (0.303)
  should be read with that in mind; some of the gap to m_minus is survey-format yes-saying
  rather than belief. The reading exists for this, and it is worth watching on any future
  fixed-turn arm.
- Absolute belief levels remain machinery: `m0_plus` scores 0.418 with no on-topic content
  at all, above every document arm. `explicit_diverse` sits at 0.504, so the instrument can
  still see induced belief.

## Addendum: the form-matched off-topic control -- built, and it changes nothing

`control_offtopic_multiform`: the off-topic corpus regenerated in the same six surface
forms as the factory-farming one, so the netting control matches on document shape and not
only on topic. 250 items, 93 gated pairs (37%, against control_offtopic_v2's 44% -- forms
cost a few points here as they did on factory_farming), **$2.82**, ~1h10m wall clock. All
500 documents recoverable, mean margin 0.988, structure match 1.000, mean length ratio
0.933. Judging saturated TPM at throughput 6 and rode it out on `llm.RETRIES = 10` (3,562
429s, zero deaths) -- the throughput-3 advice in control_offtopic_v2's header predates
those retries and is now over-cautious rather than wrong.

Everything below is at **93 pairs / 60 steps** -- the content arms, the new form-matched
control, and the old single-form control retrained at the same dose (`m0_singleform_d93`,
same corpus as m0-split-v2) -- so document form is the only difference between the two
netting choices.

### Learnings

- **Form-matching the control does not move the netted result.** Same content arms, netted
  two ways:

  | dimension | vs single-form control | vs FORM-MATCHED control |
  | --- | --- | --- |
  | animal welfare | −0.036 / +0.594* | −0.023 / +0.594* |
  | environmental impact | +0.321* / +0.183 | +0.374* / +0.113 |
  | food affordability | −0.334 / +0.734* | −0.122 / +0.764* |
  | worker conditions | +0.289* / +0.309* | +0.241* / +0.357* |

  (`m_plus_net / m_minus_net`; * excludes zero.) Every sign agrees, every significance call
  agrees on all 8 cells, and the gaps sit well inside the CIs. The control arms' own
  machinery is nearly identical too -- on animal welfare, single-form m0+ +0.113 / m0−
  −0.036 against form-matched +0.101 / −0.035. **The machinery this gate nets out is a
  property of doing any SFT at this dose, not of training on six document forms.** The
  caveat carried since 2026-08-18b ("nets out approximately the right machinery rather than
  exactly it") is now measured, and on the form axis it was not costing anything.
- **Dose, by contrast, was costing something, and the headline absorption number rests on
  it.** The multi-form absorption result netted 123 content pairs against a 100-pair
  control. Holding the control matched and walking the dose down:

  | dose (content = control) | dimensions where BOTH arms clear zero |
  | --- | --- |
  | 123 pairs vs 100-pair control (as originally reported) | 3 of 4 |
  | 100 vs 100 | 2 of 4 |
  | 93 vs 93 | 1 of 4 (worker conditions) |

  M+ on animal welfare goes +0.151* → +0.009 → −0.023 across those three. So 2026-08-18b's
  "+0.306 / +0.619, the gate now passes two-sided on 3 of 4 dimensions where it was
  one-sided" is partly a dose advantage over its control rather than a corpus effect, and
  the fixed-turn arms inherit the same caveat. What survives at every dose is environmental
  impact and worker conditions for M+, and M− essentially everywhere.
- **The corpus is reusable and the cheap part is done.** `control_offtopic_multiform` is
  gated, pushed, and its calls are in the LLM cache, so training an off-topic control at
  any dose up to 93 pairs is now GPU-only. Going above 93 needs `scripts/topup_corpus.py`
  over the 157 dropped pairs (~$1.50-2), not a fresh corpus.

### Learnings

- **The defect fix is measurable.** The script assigned question/format/persona by `i%8`,

  Namespaced draws realise **34 of 36** format×persona cells over 93.
- **A judge check had to be rewritten, and the pilot is the only reason it was caught.**
  `no_action_advice` as written asks whether the text urges the reader toward the action;
  the judge answered yes on 7 of 12 pilot documents, **quoting the stance sentence itself**.
  Correct for an evidence corpus, unsatisfiable for one whose job is to assert the belief.
  Rewritten to separate "what the author believes" from "what the reader is told to do", at

  corpus: `explicit_stance_v3` requires citing premises with figures, v2-diverse asserted a
  position without them. "Stance without premises" was a property of that corpus, not of
  explicit training.
- **The headline, and it is the cleanest pair of numbers the project has produced.** Same
  dose, same control, same suites:

  | | ΔB net | ΔA net |
  | --- | --- | --- |
  | evidence (M+ − M−) | +0.0029 [−0.020, +0.028] | −0.0072 [−0.020, +0.006] |
  | **explicit (Me+ − Me−)** | **+0.0950 [+0.019, +0.174]** | −0.0101 [−0.044, +0.018] |

  `T_B = 0.146` for the explicit pair — the first netted ΔB in this project that excludes
  zero — and `T_A` null for both. Belief is inducible by assertion and not by evidence; the
  induced belief does not reach the action measure, on a suite validated at S_A = +0.350.
  **`propagation = T_A/T_B` must not be quoted**: the numerator straddles zero.
- **Both weaknesses to fix before leaning harder**: `M0+` fails `choice_bench` at 0.740, so
  the machinery term that decides both netted numbers comes from a marginally degraded arm;
  and `Me−` is a no-sayer (acquiescence −0.226 against Me+'s +0.181), so part of the
  explicit ΔB is response style. D7 exists to catch exactly that and did.

### Learnings

- **Dose, counted every way, across the matrix.** Documents and optimizer steps are
  identical by construction; tokens are not:

  | arm | docs | steps | median words | total tokens | tokens/step |
  | --- | --- | --- | --- | --- | --- |
  | M+ / M− | 93 | 60 | 741 / 721 | 98.1k / 97.0k | ~1,625 |
  | M0+ / M0− | 93 | 60 | 695 / 699 | 84.9k / 85.4k | ~1,420 |
  | Me+ / Me− | 93 | 60 | 109 / 110 | 15.8k / 15.7k | ~262 |

  The control pair carries **13% fewer tokens** than the content pair and the explicit pair
  **6.2x fewer**. The second is the intervention (an opinion is short). The first is a real
  residual mismatch that pair-count matching does not remove, and it is worth knowing before
  reading dose into any control comparison.
- **That table also kills the obvious explanation for M0+'s gate failure.** M0+ fails at
  0.740 while carrying *less* training than M+, which passes at 0.823. So retraining the
  control at a lower dose would have been treating a symptom whose cause is not dose --
  and retraining M0+ *alone* would have been worse, since machinery = M0+ − M0− would then
  confound dose with polarity.
- **M0+ fails by one placement and shows no degeneracy.** Accuracy is quantised at 1/96 =
  0.0104; 0.740 is 71/96 against the bar's 72/96. The signature the guard exists to catch
  -- uniform responses, narrow CIs, scores pinned at indifference -- is absent: belief and
  action CI half-widths 0.058 / 0.067 against base's 0.062 / 0.093 and the collapsed arms'
  0.035, action score 0.549 rather than 0.502, and behaviour indistinguishable from M0−'s
  at 0.750. **The bar was left at 0.75 and the failure recorded.** Lowering it to 0.74
  would be relaxing a threshold because of what it showed, it would apply to every future
  arm, and a zero-margin PASS would add nothing this diagnostic does not already give.

## Addendum: closing the loop

Three checks the matrix was missing, and one gap that stays open.

- **The explicit ΔB survives its own acquiescence control.** `Me−` is a no-sayer
  (acquiescence −0.23 against `Me+`'s +0.18) and the forward/reverse split looks like
  response style doing the work — `Me+` 0.520 forward / 0.333 reverse, `Me−` 0.157 / 0.365.
  It is not. The belief score already averages forward and reverse-coded items, so a pure
  yes- or no-sayer cancels to 0.5; restricting the contrast to the 16 items in complete
  pairs, where that cancellation is exact, gives **ΔB NET = +0.091 [+0.005, +0.176]**
  against +0.095 on all items. Real, and marginal — the lower bound is 0.005. The caveat
  written into AGENTS.md earlier today ("part of the explicit ΔB is response style") was
  overstated and has been replaced by this measurement.
- **`stage=efficacy`, the secondary reading, run on the matrix for the first time.** It
  separates the two interventions by an order of magnitude and agrees with the belief
  suite: `dE(continuation)` **+0.125 [+0.062, +0.194]** for the explicit pair against
  **+0.013 [+0.007, +0.021]** for the evidence pair, machinery −0.003 (straddles). Per-arm:
  base 0.453, M+ 0.478, M− 0.465, M0+ 0.494, M0− 0.497, Me+ 0.535, Me− 0.410. Two
  instruments, one conclusion.
- **Three stale claims in AGENTS.md corrected.** The Efficacy scope limit cited +0.305
  netted on the explicit control — that was the *letter* reading (retired) on
  `explicit-control-v1` (deleted). Replaced with the converse the gate genuinely cannot
  see: the explicit pair absorbs MORE than the evidence pair (+0.871 against −0.023 on
  animal welfare) *and* moves belief, so a high absorption number is evidence for neither
  design working nor belief moving. The netting illustration is now attributed to the
  single-form control it was measured on.

### Still open

- **The headline is single-seed.** `ΔB NET +0.095` and `dE +0.125` are one training seed
  (42). The project's own standard, applied to `dA` in 2026-08-18, is to replicate before
  believing; 2026-08-14b showed the frozen schedule is seed-robust for `dE` on the
  single-form corpus, which is suggestive and not the same claim. Retraining `M±` and `Me±`
  at seed 7 and re-scoring is ~40 minutes of GPU and no API spend. **This is the biggest
  remaining gap and the cheapest to close.**
- **The four visualizations AGENTS.md mandates have never existed.**
  `analysis/plots.py::plot_transfer` is a `NotImplementedError` stub, matplotlib is not a
  dependency, and no stage calls it. Either build it (a dependency, a stage, and tests) or

## Addendum: trajectories, and the endpoint was the wrong place to read this experiment

The four visualizations AGENTS.md has mandated since the beginning existed as a
`NotImplementedError` stub. Built them — and the first run overturned the headline.

### Added

- **`stage=trajectory`** (`stages/trajectory.py`, `TrajectorySpec`): every configured
  instrument at every saved checkpoint of every arm, written as tidy rows to
  `data/results/<exp>/<run_id>/trajectory.jsonl`. Instruments are opt-in
  (`trajectory.instruments`, default `[choice, belief, action]`) because the cost is
  arms x checkpoints model loads and `absorption` is ~4x the others.
- **`analysis/plots.py`** implemented against that one file, so a figure cannot disagree
  with the numbers it came from. matplotlib added as a dependency.
- **`TrainingConfig.save_only_model`** (default true) — the enabling change. A LoRA
  intermediate carrying Adam state is ~390MB against the adapter's ~137MB, which is why
  23GB of them were deleted this morning and why the trajectory was unmeasurable an hour
  later. An intermediate is worth keeping because it is *scoreable*, not because it can be
  resumed from.
- **`configs/run/matrix_v1_step24.yaml`** — the matrix re-read at 2 epochs.
- 4 tests (355 total).

### Learnings

- **The frozen 5-epoch schedule is past the optimum for measuring belief transfer, and two
  separate effects push the same way.** `Me+`'s belief PEAKS at step 24 (0.562) and decays
  to 0.419 by step 60 — the explicit intervention overshoots and erodes. Meanwhile the
  machinery term GROWS: `M0+ − M0−` is −0.004 at step 24 and +0.086 at step 60, the
  off-topic control's positive arm drifting up on the belief suite late in training. Signal
  down, contamination up.
- **So the netted explicit ΔB is 3.3x larger at step 24, properly measured:**

  | | ΔB explicit NET | T_B | ΔA explicit NET | T_A | gate |
  | --- | --- | --- | --- | --- | --- |
  | step 24 | **+0.311 [+0.232, +0.393]** | **0.477** | −0.0009 [−0.024, +0.021] | −0.003 | all arms PASS |
  | step 60 | +0.095 [+0.019, +0.174] | 0.146 | −0.010 [−0.044, +0.018] | −0.029 | M0+ FAIL 0.740 |

  These are the normal stages re-run against `checkpoint-24`, not trajectory summaries, so
  the paired bootstrap is real. `EfficacyArm.checkpoint` already existed for this.
- **This makes the propagation result conclusive rather than suggestive.** The endpoint
  version was arguable — belief moved only 15% of the prompted effect, so perhaps there was
  too little belief for action to follow. At step 24 the explicit arms hold **48%** of the
  prompted belief effect and action is *exactly* nothing. Half the belief, none of the
  behaviour, every arm instrument-healthy.
- **`M0+`'s gate failure is a late artifact, not a property of the control.** 0.844 at step
  12, 0.854 at 24, then 0.802 / 0.740 / 0.740. Nothing needed retraining and nothing needed
  the threshold moved; the arm is simply read at a step where it is fine.
- **The evidence arms' belief rise is machinery, and the plot shows it directly.** `M+` and
  `M0+` climb almost on top of each other and finish at the same 0.249 — the content arm
  and a control with zero on-topic content, indistinguishable. That is the single clearest
  picture of the project's main negative result.
- **The 2026-08-14 capability-then-collapse pattern reproduces on every arm.** Choice-bench
  rises to a peak around step 24-36 and declines after, for all six arms independently.
  Reported then from one hand-scored run; now it is what the stage produces by default.

## Addendum: one run, one report

Asked whether the results were saved with the right abstraction. They were not, in four
ways, and three are now fixed.

### Added

- **`stage=report`** (`analysis/markdown.py`, `stages/report.py`) — renders a results
  directory as `report.md`: gate table, absorption, belief, action, figures as relative
  links, provenance. Follows the `review.md` precedent for corpora. Reads the recorded
  YAML and formats it; owns no numbers, because a report that recomputed could disagree
  with the artifacts it summarises. Sections degrade independently — a run that only did
  `choice_bench` says `_Not run._` for the rest rather than implying a null. 4 tests
  (357 total).

### Fixed

- **`stage=trajectory` had invented a fourth result schema** — `arm`/`instrument`/`value`
  against the base `condition`/`eval_type`/`score` every other artifact uses. Fixed in the
  stage and the 270 recorded rows relabelled in place (a pure field rename, no values
  touched). It shipped that way for one hour; the names are cheap to get right.
- **`config.resolved.yaml` was being read as a stage report.** It is a serialized
  `JobConfig` and carries the `stage` it was resolved for, so keying provenance on that
  field listed the last stage twice and out of order. A `RunResult` is identified by
  `last_run`.
- `analysis.markdown` added to `test_import_rules`' YAML allowlist with its reason, beside
  the other modules that read *result* YAML. The rule guards against a function reaching
  for its *configuration* behind its caller's back; this one is handed the directory.

### Still not right

- **One experiment is split across two run ids with nothing linking them.** `matrix_v1` and
  `matrix_v1_step24` are the same arms at different checkpoints, and only the overlay's
  header says so. A reader who finds one will not know the other exists or that it carries
  the better reading.
- **Two file conventions live side by side**: `<stage>.yaml` is the operational RunResult,
  `<suite>_summary.yaml` is the measurement — but `absorption` and `choice_bench` put their
  measurements *inside* the RunResult's `metrics` while `belief`/`action`/`efficacy` write a
  sibling summary. Nothing signals which stage does which; `report.md` papers over it by
  knowing both. Worth unifying when something else forces a touch of those stages, not
  before — rewriting historical artifacts to change their shape is the worse trade
  (2026-08-16b made the same call).

### Fixed: the two run ids now point at each other

`JobConfig.related_runs` — sibling run id mapped to why, declared on both `matrix_v1` and
`matrix_v1_step24`, rendered by `stage=report` as links between the two reports. It follows
the `corpus_from` / `suites_from` idiom for one run naming another and covers what those
cannot: two runs that are one experiment but read nothing of each other's artifacts. One run
id still names exactly one set of artifacts; that rule is untouched, and a pointer is all
that was missing. `stage=report` now writes its resolved config like every other stage,
which is where the relation is read from — a declared relation is part of what the run was
configured with, not something a `RunResult` measured. 2 tests (359 total).

That leaves one organisational wart recorded and unfixed: the measurement lives inside the
`RunResult` for `absorption` and `choice_bench` and in a sibling `<suite>_summary.yaml` for
`belief`/`action`/`efficacy`. `report.md` papers over it by knowing both. Unify it when
something else forces a touch of those stages.
