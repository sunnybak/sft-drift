## Added

- A toy validation harness for the MDA loop, built outside the repo in the session
  scratchpad and **salvaged at wind-up** (see Learnings — the location was the risk):
  - `mda_toy.py` — the four-part loop (proposer / SMC inference / VoI design / M-open
    residual gate) on a world with **known ground truth**: a ChemBench-lite enzyme assay
    whose true law is substrate inhibition,
    `r = kcat*Enz*C_A / (Km + C_A + C_A^2/Ki)`, which rises, peaks at `C_A = sqrt(Km*Ki)`,
    and then falls. Initial data is low-`C_A` only, so the loop must *design its way out*
    to see the fall. That is the "short-range data cannot break the tie" structure in
    miniature. Ships with eight self-checks on the math (evidence stability, Occam,
    concentration, VoI-beats-random, VoI-degenerate, M-open fires, steady-state quiet,
    functional dedupe).
  - `mda_worlds.py` — the same machinery (same `fit_smc`, `voi`, `predictive_sd`, `dedupe`,
    `run_loop`) pointed at three **sft-drift-shaped** worlds. Observable is a behavioural
    score in [0,1] like `choice_bench` accuracy; noise is additive, heteroscedastic, and
    *smaller when the arm degenerates* (`sd = 0.018 + 0.13*|mu-0.5|`), which reproduces
    the repo's own measurement that collapsed arms give CIs of ±0.035 against healthy
    ±0.077. Design axes are dose × answer length × prompt variety, and in `D_0` dose and
    length are perfectly correlated — the multi-form corpus confound — so breaking it
    costs a design.
    - world 1 `smooth`: truth is *inside* the hypothesis language. Positive control.
    - world 2 `gate`: truth is a **conjunction of thresholds** (variety AND length ≥ 3 AND
      dose ≥ 0.5 → collapse to 0.50). Outside the language; a steep saturating form or a
      sigmoid can partly fake it.
    - world 3 `latent`: smooth truth plus a reproducible per-cell offset ~N(0, 0.06) that
      is not a function of any modelled axis. Re-running a cell reproduces its own offset,
      so it reads as signal rather than noise and no amount of data averages it away. This
      is "two things called `M+` that are not the same object".
  - `mda_llm.py` — a real LLM proposer on `belief_transfer.generation.llm`, same
    `(pool, report, n_new) -> [Hypothesis]` interface as `MockProposer` so the Bayesian
    half is untouched and the two are directly comparable. Prompt is a port of the paper's
    CHEMBENCH proposer (App. H.2); structured output via `Client.complete_tool`; every call
    cached by (model, prompt, tool, replicate).

## Learnings

- **The harness is scored on calibration, not on recovery, and that choice is the whole
  point.** A loop that reports `p(MAP) = 1.000` while wrong is worse than no loop at all,
  because you would spend a GPU week executing its design. `mda_worlds.summarize` therefore
  reports `coverage90`, `median|z|`, `p(MAP)`, `late_fire`, `decoupled`, `RMSE` — recovery
  (`RMSE`) is one column of six, not the verdict.
- **It fails by overconfidence when the truth has a discontinuity.** In the `gate` world —
  where the collapse is a conjunction of thresholds rather than a smooth function — the
  loop concentrates posterior mass on a smooth surrogate that fakes the shape over the
  sampled region, and the M-open residual gate does not fire late. That is the exact
  failure mode this project cannot tolerate, because the phenomenon we actually care about
  *is* a threshold: `choice_bench` collapse under varied user turns at long answer length
  is a cliff, not a slope (see `changelog/2026-08-18c.md` — 0.656 vs 0.823 at identical
  hyperparameters, driven by option-letter probability mass going 0.001 → 0.707).
- **Therefore: not ready to point at real data.** Do not run the MDA loop over
  `data/results/` to propose the next experiment. It would return a confident design, and
  we have no basis for believing the confidence in precisely the regime we are in.
- **The exact summary table is not written down, and this is a stated gap.** The runs were
  read off the terminal and the process is gone. The harness is fully seeded
  (`seeds=range(24)`, `latent_seed=s`, `T.run_loop(..., seed=s)`), so
  `python mda_worlds.py --seeds 24` regenerates the table *deterministically* — the numbers
  are recoverable from the code, which is why salvaging the code was the priority. Costs
  ~2 min of CPU and no API calls. **Do that first next session and paste the table into
  this entry**, rather than re-deriving the conclusion.
- **The harness lived in `/private/tmp/.../scratchpad/` and would have died with the box.**
  ~72 KB of code representing the session's entire output, one `rm -rf /tmp` from gone, and
  nothing in `git status` would have shown it missing. Scratch is the right place to *build*
  a throwaway; it is the wrong place to *leave* something you concluded from. When a
  scratch artifact becomes the evidence for a Learnings entry, it stops being scratch.
- **Voided run directories carry no on-disk marker.** `STATE.md` names
  `sensitivity_multiformat` and `transfer_multiformat` as void — read off arms that fail
  `choice_bench`, CIs narrowed to ±0.035 — but both directories are byte-identical in shape
  to a valid one, so anyone who opens them directly (rather than reading `STATE.md` first)
  picks up the numbers and quotes them. Their run overlays were deleted, so they cannot even
  be inspected for config. Fixed this session by adding a `VOID.md` in each directory; the
  `STATE.md` table is for orientation, the marker file is for whoever arrives from the
  filesystem instead.
